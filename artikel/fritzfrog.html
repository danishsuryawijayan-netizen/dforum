KASUS LAB: FritzFrog, Cacing Golang yang Ngamuk dan Bikin Kiamat di Sistem Root

Oleh: Redaksi DForum (Analis Independen) | Tanggal Rilis: 28 Oktober 2026 | Kategori: Investigasi Worm & Botnet

YOGYAKARTA — Ini bukan virus sembarangan. Namanya FritzFrog, sebuah Worm (cacing) mutakhir yang ditulis pake bahasa Golang (Go). Bedanya sama virus lain, dia nyebar mandiri lewat jaringan pake protokol P2P (Peer-to-Peer) dan nekat nge-Brute-Force layanan SSH. Tanggal 28 Oktober, kami narik sampel file .elf berukuran 16.6 MB dari MalwareBazaar. Dia nggak cuma nambang kripto (CoinMiner), tapi punya misi bikin "pintu belakang" (Backdoor) dengan nambahin user baru di sistem yang kena infeksi.

Nyebar Tanpa Diundang

Prosedurnya standar lab. File diunduh, diekstrak di PC asli, terus dikirim ke VM REMnux pake HTTP Server lokal. Analisis statis kami jalanin pake file, upx, dan strings. Tapi, karena ini file Golang, hasil strings-nya super berantakan (noisy) dan nyampur sama memori internal Go.

Jeroan Golang yang Berantakan

Pas dibedah, file ini berukuran 16.6 MB, dan setelah di-unpack dari UPX, melar jadi 22.3 MB. Ini yang kami temuin:

  • Ada indikasi protokol jaringan: ssh, dns, udp, ftp.
  • Ditemukan string iaesudonode. Ternyata ini perintah rahasia buat bikin user baru.
  • Ada indikasi kredensial default: root, 1234, dan IP 2.5.4.6 (kemungkinan password default perangkat IoT).

Aksi Ngamuk sebagai Root (Analisis Dinamis)

Ini bagian paling gila. Kami eksekusi file-nya di dalem VM pake akses Root (sudo ./malware3.elf).

  • Langsung Kabur: Malware ini langsung jalan di background, nggak nahan terminal.
  • Efek Samping Fatal: Beberapa saat kemudian, sistem tiba-tiba nampilin layar login baru dengan user bernama node.
  • Kiamat Sistem: Worm ini berhasil nambahin user node ke /etc/passwd. Ini taktik Persistence (pintu belakang) biar hacker bisa masuk kapan aja. Karena dia jalan sebagai Root, dia juga ngerusak kredensial sistem. User asli (remnux) langsung gagal login (Password Authentication Failed).

Pembersihan Darurat (Incident Response)

Karena dia udah dapet akses Root (tingkat tertinggi di Linux) dan ngerusak file autentikasi, bersih-bersih manual udah nggak efisien. Langkah yang kami ambil:

  • Power Off: Matiin paksa mesin virtual.
  • Rollback Snapshot: Balikin VM ke kondisi terakhir sebelum infeksi (Sebelum-FritzFrog). Ini best practice mutlak: kalau sistem udah di-root, hancurin dan pulihin dari backup.

Catatan Redaksi (Pelajaran Penting)

  • Waspada Golang: Malware berbasis Go ukurannya gede dan susah dianalisis pake strings biasa.
  • Bahaya Root: Jalanin Worm sebagai sudo itu sama aja ngasih dia kekuatan dewa buat ngubah password dan bikin user baru.
  • Snapshot adalah Nyawa: Tanpa snapshot, kami harus nginstal ulang REMnux dari nol gara-gara ulah si cacing ini.

DENGERIN, BEGO! Dokumen ini dibuat cuma buat riset edukasi anonim. Kami nggak nyebarin virusnya. Kalau lo pake info ini buat nyerang orang, itu dosa lo sendiri, jangan bawa-bawa nama DForum.

node (Backdoor yang dibuat malware).

Network
